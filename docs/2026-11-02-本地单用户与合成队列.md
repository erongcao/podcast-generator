# 2026-11-02 · 本地单用户与合成队列

版本 `0.4.5-web`（`gui/web/version.py`）。这是一次收口，不是新功能。

## 为什么这样改

看板不登录也能用。`get_current_user` 只挂在 `/api/auth/me` 上，主页面直接调 `/api/voices`、`/api/parse`、合成和 `/api/credentials`。如果每个接口都要求登录，现在的用法会断。

所以本机限制代替强制登录：服务本来就绑 `127.0.0.1`，中间件再挡住「以后如果绑到 `0.0.0.0`」的情况。

合成原来用 FastAPI `BackgroundTasks`。连续点两次就会两份一起跑，日志从同一个 WebSocket 灌进来，分不清是哪一次。脚本生成也走这条通道，会和合成的日志混在一起。

音色存在两处：SQLite `voice_clones`，以及 `~/Library/Application Support/PodcastGenerator/voices/voices.json`。原来先查 JSON。网页上改过的音色在数据库里，一份过期的 JSON 会把修改盖掉。

`voice_clones` 的 MiniMax 三列（`minimax_voice_id`、`clone_status`、`clone_error`）以前只在启动时 ALTER。注释写着项目没有 Alembic versions 目录，这已经不对。启动器 `bin/podcast-gui.sh` 仍然不跑 alembic，所以启动 ALTER 不能删。

## 改了什么

**本机访问**（`gui/web/local_only.py`）

- 挡住 `/api`、`/output`、`/ws`。
- 放行 `/`、`/login`、`/editor`、`/health`、`/static`。
- 算本机的地址：`127.0.0.1`、`::1`、`localhost`、`::ffff:127.0.0.1`，以及测试客户端的 `testclient`。
- 拒绝时 HTTP 403，正文 `{"detail":"仅允许本机访问"}`。WebSocket 直接关，关闭码 1008。
- 用纯 ASGI 中间件，加在 `SessionMiddleware` 之后，这样它在最外层。不用 `BaseHTTPMiddleware`，那个会弄断 WebSocket。

**一条队列**（`gui/web/jobs.py`）

- 一个守护线程，合成三个引擎和脚本生成都进这里。
- 接口马上返回 `status: "queued"`，另外给 `task_id` 和 `ahead`（前面还有几个，正在跑的算一个）。
- 工作线程里设置 `current_task_id`。`ws_manager.push` 在消息自己没带 `task_id` 时补上。ContextVar 不跨线程，所以必须在工作线程里设；豆包的日志回调就在这个线程的 `asyncio.run` 里。
- 合成行先写成 `pending`，轮到它才改成 `running`。没有用户、建不了行时，任务照旧跑，只是不记数据库。
- 直接调用线程函数、不传 `synth_id` 时，行为跟以前一样：当场建一条 `running`。
- 进程启动时，把上一轮留下的全部 `pending` 和 `running` 标成失败，错误文案是 `orphaned by process restart`。做完这件事才 `start_worker()`，避免刚接过的任务被标失败。
- 删掉了 SIGINT/SIGTERM 里写日志再 `sys.exit(0)` 的处理。那会跳过 uvicorn 自己的收尾。正常退出仍由 shutdown 钩子往 `output/web_server.log` 追加一行。

**看板**（`gui/web/static/js/app.js`）

- 提交合成或脚本生成时记下返回的 `task_id`。
- `log` / `progress` / `done` / `error` 如果带了别的 `task_id`，就丢掉。
- `script_done` 始终收下。脚本那条任务的 `error` 也会收下，用来把「生成脚本」按钮复位。
- `ahead > 0` 时多写一行，说明前面还有任务。

**音色**（`voice_resolver.py`）

- `resolve()` 先查 SQLite，没有再查 JSON。
- 数据库查询失败时仍退回 JSON。CLI 和不存在数据库的环境保持原样。
- 这一轮不改 CLI / Qt 去写数据库。它们继续写 JSON，解析器还能读到。

**凭证**

- `GET /api/credentials` 只返回 MiniMax 密钥在不在、来源是不是 `config.json`，以及豆包的 app id / token 在不在。
- 不再返回前缀和长度。密钥仍是 `config.json` 里的明文。

**数据库**

- 新修订 `d5f8a21c6e40`，`down_revision` 是 `86e2ab3c95ab`。
- 表不存在，或三列已经在，就跳过。降级时也只删存在的列。
- `app.py` 里的 `_ensure_voice_clone_columns()` 保留，注释改成说明两条路都要幂等。

## 故意没做

- 不要求登录才能用看板，也不删注册页。
- 不删 `gui/qt/`、`gui/main_window.py`、`podcast_generator.py`。桌面入口可能还在用。
- 不把 `ApiKey` 收成加密存储，也不删没用到的 `ApiKey` / `Article` 表。
- 不把合成、脚本、音色改成「谁登录就记谁的」。现在仍是 `get_default_owner()`：第一个管理员，没有管理员就第一个用户。
- 不在这次跑 `alembic upgrade` 去改 `~/.podcast-automation/podcast.db`。下次正常启动时，启动 ALTER 会自己补列。

## 怎么验证

```bash
cd ~/Documents/podcast-generator
python -m pytest tests/test_voice_resolver.py tests/test_jobs.py tests/test_local_only.py tests/test_voice_clone_migration.py
```

重启正在跑的看板之后，上一轮没跑完的合成会变成失败。这是预期，不是把好任务弄丢。
